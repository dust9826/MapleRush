## 한눈에 보기 (5문답)

**Q1. 무엇을 만드나요?**
스피드 로그라이트인 메이플 러시에 **"시간"을 성장 지표**로 노출한다. 로비에는 최고 기록판, 인게임에는 현재 판 경과 시간을 상시 표시하며, **글로벌 리더보드**로 다른 유저와도 경쟁한다. → §1

**Q2. 왜 만드나요?**
매 층마다 적 HP가 +20%(합연산) 증가하는 스케일링 하에서, 성장 실감을 **"스테이지 클리어"** 이외의 축으로 확보하기 위함. 시간 = 마스터리의 시각화. → §1

**Q3. 무엇을 기록하나요?**
`(도달 층, 층 내 진행도, 누적 시간)` 튜플. 정렬 우선순위는 **층 > 진행도 > 시간(짧을수록 상위)**. 랭킹 패키지가 단일 numeric score만 지원하므로 이 튜플을 하나의 정수로 인코딩. → §3 / §6

**Q4. 언제 시간이 흐르나요?**
첫 스테이지 조작 가능 시점부터 시작, 사망/게임오버/최종 클리어 시 종료. **ESC 일시정지 중에는 정지**, 스테이지 간 로딩·테마 선택·노드 선택·상점 중에도 정지. → §4

**Q5. 무엇은 하지 않나요?**
인게임 타이머의 **색상 변화 없음**(잔잔한 표시). 시즌/사이클 리더보드는 초기 미도입 (필요 시 `ranking-advanced-package`로 확장). → §5·§7

## 1. 배경 & 목표

### 1.1 문제 정의

메이플 러시는 스피드 로그라이트 장르로, 다음 두 축의 성장 압력이 존재한다.

- **성장 압력**: 메타 업그레이드, 능력, 무기 등으로 플레이어가 강해짐
- **긴장 압력**: 매 층마다 적 HP +20% 합연산 증가 → 후반부로 갈수록 도전 유지

이 구조는 긴장감을 유지하지만, **"성장했다는 실감"이 스테이지 진행 이외의 축에서 드러나지 않는** 문제가 있다. 1인 플레이 게임이므로 **비교 대상**이 부재하여 실력 향상을 체감하기 어렵다.

### 1.2 목표

1. **성장 시각화**: 시간 = 성장의 지표. 같은 진행도라도 클리어 타임이 줄어들면 실력 향상이 명확.
2. **자기 경쟁**: 과거의 자신과 비교. 매 판 이전 기록을 확인 가능.
3. **글로벌 경쟁**: 초기 버전부터 리더보드 연동. 다른 유저 기록과 순위 비교.
4. **스피드 로그라이트 정체성 강화**: "빠르게 뚫는 즐거움"을 UI 전면에 배치.

### 1.3 비목표 (초기 버전)

- 카테고리별 랭킹 분리 (캐릭터별, 무기별 등) — 추후 확장
- 시즌 / 주간·월간 사이클 리더보드 — 추후 `ranking-advanced-package`로 마이그레이션
- 리플레이 / 고스트 데이터 — 추후 확장

## 3. 기록의 정의

### 3.1 게임 구조 용어 정리 (`FloorManager.mlua` / `StageManager.mlua` 기반)

| 용어 | 정의 | 예시 |
|---|---|---|
| **런 (Run)** | 로비 → 첫 층 시작 → 게임오버 or 최종 클리어까지의 한 판 | - |
| **층 (Floor)** | 런 내 진행 단위. 순차적으로 증가 (1층 → 2층 → 3층) | 한 런 = 최대 3개 층 (거울던전식) |
| **테마 (Theme)** | 각 층에서 선택하는 맵 종류. 한 런 내 중복 선택 불가 | 오르비스 / 엘나스 / 폐광 |
| **스테이지 (Stage)** | 층 내부의 개별 전투 단위. 타입은 `normal` / `shop` / `boss` | 셔플 덱 방식으로 순서 결정 |
| **층 클리어** | 해당 층의 보스 스테이지 클리어. 다음 층으로 진행 | - |

**중요**: 원래 대화에서 "테마 클리어"라고 표현된 것은 **"층 클리어"** 를 의미. 이후 문서 및 코드에서는 **층(Floor) 기준**으로 통일.

### 3.2 진행도 판정

**"도달"의 기준은 각 스테이지의 클리어 시점**이다.

- 층 내 N번째 스테이지를 클리어하면 진행도 = "N층 스테이지 N 클리어"
- 층의 보스 스테이지 클리어 → 층 클리어. 다음 층 진입 시 진행도 = "(N+1)층 스테이지 0" (대기 상태)
- 스테이지 도중 사망은 이전 스테이지의 진행도만 유지

**층 내 진행도 표현**: `StageManager`의 `NormalsClearedThisFloor` + `ShopDoneThisFloor` + 보스 클리어 여부를 조합한 단일 정수로 정규화 (§6.1 인코딩 참조).

### 3.3 비교 규칙 (베스트 판정)

두 기록 A, B의 우선순위:

1. **층 번호가 큰 쪽이 우위**
2. 층이 같으면, **층 내 진행도가 큰 쪽이 우위**
3. 층·진행도가 같으면, **누적 시간이 짧은 쪽이 우위**

**예시:**

| 기록 | 판정 |
|---|---|
| (2층, 스테이지 1, 12분) vs (1층, 보스 클리어, 08분) | 앞의 것 우위 (더 깊이) |
| (2층, 스테이지 3, 15분) vs (2층, 스테이지 4, 20분) | 뒤의 것 우위 (같은 층 내 더 깊이) |
| (2층, 스테이지 3, 15분) vs (2층, 스테이지 3, 12분) | 뒤의 것 우위 (같은 진행도 → 시간 짧음) |

### 3.4 시간 단위

- **저장**: 초 단위 (부동소수 `number`, 예: `754.32`)
- **인게임 표시**: `MM:SS` (초 단위, 매초 갱신)
- **베스트 기록 표시**: `MM:SS.CC` (센티초 2자리까지)
- 1시간 초과 시 `HH:MM:SS` / `HH:MM:SS.CC` 로 자동 확장

### 3.5 테마 맵 매핑 (구현 상태 확인 완료)

| 테마 | 일반 스테이지 맵 | 보스 맵 | 상태 |
|---|---|---|---|
| 엘나스 | `map/ElnathLevel.map` | `map/ElnathLevel_Boss.map` | ✅ 구현 완료 |
| 오르비스 | `map/OrbisLevel.map` | `map/OrbisLevel_Boss.map` | ✅ 구현 완료 |
| 폐광 | `map/DeepMineLevel.map` | `map/DeepMineLevel_Boss.map` | ✅ 구현 완료 |
| (공용 상점) | `map/map04.map` | - | ✅ 구현 완료 |

기록 시스템은 **테마 종류를 저장하지 않는다** — 유저 관점에서는 "3개 테마 중 어떤 걸 골랐는지"보다 "몇 층까지 갔는지"가 실력의 지표. 다만 통계용으로 각 층에 어떤 테마를 선택했는지 부가 정보로 저장 가능 (§6.1 옵션).

## 4. 런 타이머 규칙

### 4.1 타이머 시작

- **첫 스테이지가 로드되고, 플레이어의 조작이 가능해지는 순간**에 시작
- 로비 → "구하러 가기"(`RequestStartRun`) 클릭 → 테마 선택 → 첫 스테이지 진입 → **첫 스테이지 조작 가능 시점**
- 테마 선택 팝업, 로딩 화면 등은 시작 전

### 4.2 타이머 정지 (시간이 흐르지 않음)

다음 상황에서는 시간이 **누적되지 않는다**:

- **ESC 일시정지 메뉴 열림 상태** (`StageManager.combatPaused`와 연동 가능)
- **테마 선택 팝업 표시 중** (`FloorManager.PhaseName == "theme"`)
- **노드 선택 팝업 표시 중** (`_InputRouter:SetContext("Node")` 상태)
- **상점 스테이지 진입 중** (`StageType == "shop"`) — 순수 전투 시간만 측정
- **스테이지 간 맵 로딩·전환 화면**

### 4.3 타이머 종료

- 플레이어 사망 → 게임 오버 화면 진입 시점에 정지
- 최종 층의 보스 스테이지 클리어 → 클리어 연출 시작 시점에 정지 (`PhaseName == "clear"`)
- 종료 시점의 값이 **최종 런 시간**으로 확정, 기록 판정 및 리더보드 등록에 사용

### 4.4 갱신 주기

- 인게임 HUD: **1초마다** 화면 갱신 (프레임 단위 갱신은 시각적 노이즈 유발)
- 내부 시간 측정은 `OnUpdate(delta)` 기반으로 정밀 계산 (초 단위 반올림은 표시 시에만)

## 5. UI 사양

### 5.1 로비 베스트 기록판 (`ui/LobbyGroup.ui`)

**위치**: 화면 **중앙 좌측**

**표시 형식:**

```
┌───────────────────────────────┐
│                               │
│   ── 나의 최고 기록 ──        │
│   2층 · 스테이지 3            │
│   12:34.56                    │
│                               │
│   글로벌 순위: #42            │  ← (선택) 초기 버전 텍스트만
│                               │
└───────────────────────────────┘
```

**케이스별 문구:**

| 상태 | 표시 |
|---|---|
| 기록 없음 (첫 플레이) | `기록 없음 — 첫 도전!` |
| 층 내 일반/상점 스테이지 도달 | `N층 · 스테이지 M` + 시간 |
| 층 보스 클리어 | `N층 클리어` + 시간 |
| 최종 층 클리어 | `전 층 클리어` + 시간 |

**폰트 / 스타일:**

- 기존 로비 UI의 톤앤매너 유지
- 시간은 기록 텍스트보다 약간 크게 (강조점)
- 색상 강조 없음
- 글로벌 순위는 별도 라인, 로딩 중일 때는 `순위 조회 중...` 표시

### 5.2 인게임 런 타이머 HUD

**위치**: 화면 **상단 중앙**

**표시 형식:**

```
        ┌───────────┐
        │   03:47   │  ← 현재 판 경과 시간 (크게)
        │  02:15.30 │  ← 이전 기록 (작게, 있을 때만)
        └───────────┘
```

**표시 규칙:**

- **현재 시간**: 큰 폰트, 항상 표시
- **이전 기록 (하단 소형 폰트)**:
  - 기록이 있으면 **항상 표시**
  - 표시 값은 **"현재 도달 진행도의 이전 최고 시간"**
    - 예: 지금 2층 스테이지 3 플레이 중이라면, 과거 기록의 `(2층, 스테이지 3)` 도달 시점 시간을 표시
    - 과거에 그 진행도까지 도달한 적 없으면 이 라인 비표시
  - 폰트 크기: 현재 시간의 약 50~60%
- **색상 변화 없음** — 잔잔하게 표시하여 시선을 뺏지 않음
- **일시정지 중**: 시각적으로 정지된 것이 명확하도록 (숫자가 멈춤)

### 5.3 글로벌 리더보드 (초기 버전)

**최소 스펙**: 로비 기록판에 **본인의 글로벌 순위**만 텍스트로 표시.

**확장 버전 (선택, 우선순위 하)**: 별도 리더보드 화면 (`GlobalRankingGroup.ui`, F3 등의 단축키로 열림) — 상위 랭커 목록 표시. `ranking-basic-package`의 기본 UI 트리거(F3)를 재활용 or 커스텀 UI 부착.

## 6. 데이터 모델

### 6.1 로컬 캐시 스키마 (DataStorage)

```lua
-- DataStorage key: "user_best_record"
{
  -- 베스트 진행도
  maxFloor = 2,              -- integer, 도달한 최대 층 번호
  maxStageInFloor = 3,       -- integer, 해당 층 내 도달한 스테이지 순번
  bestFloorPhase = "normal", -- string, "normal" | "shop" | "boss_cleared"
  bestTime = 754.32,         -- number, 위 진행도 도달까지의 최소 누적 시간 (초)

  -- 리더보드 등록용 인코딩 스코어 (§6.3 참조)
  bestScore = 20230999985170, -- integer

  -- 스테이지별 세부 기록 (인게임 HUD "이전 기록" 표시용)
  -- key = "floor-stageOrdinal-phase", value = 클리어 시점 누적 시간
  stageRecords = {
    ["1-1-normal"] = 45.20,
    ["1-2-shop"] = 60.15,
    ["1-3-normal"] = 92.15,
    ["1-4-boss"] = 148.30,
    ["2-1-normal"] = 210.50,
    -- ...
  },

  -- 통계 (선택)
  totalRuns = 42,
  updatedAt = "2026-07-04T15:30:00"
}
```

### 6.2 리더보드 등록 스키마 (`ranking-basic-package`)

`RankingDataStorageLogic:SetScoreAndWait(score, tag)` 호출 시 등록되는 데이터:

- `score`: §6.3의 인코딩 정수
- `tag`: `MM:SS.CC` 포맷의 시간 문자열 (표시용, 랭킹 조회 시 원본 시간을 재구성하기 위한 힌트)
- 자동 저장: 플레이어 프로필 코드 + 닉네임

### 6.3 Composite Key → Single Score 인코딩

랭킹 패키지는 단일 정수 점수만 지원하므로 `(층, 진행도, 시간)` 튜플을 하나의 정수로 인코딩한다.

**인코딩 공식:**

```
score = floor * 10^11
      + stageProgress * 10^8
      + (10^8 - clamp(timeInCentiseconds, 0, 10^8 - 1))
```

여기서:
- `floor`: 도달 층 번호 (1, 2, 3, ...)
- `stageProgress`: 층 내 진행 순번 (§3.2 정의; 예: 스테이지 순번 * 2 + 클리어 플래그로 단조 증가)
- `timeInCentiseconds`: 누적 시간 × 100 (센티초 단위)

**동작 원리:**
- 더 높은 층이면 항상 상위 (10^11 자릿수 우위)
- 층이 같으면 진행도가 큰 쪽이 상위 (10^8 자릿수 우위)
- 층·진행도가 같으면 **시간이 짧을수록 큰 remainder** → 상위

**정합성 예시:**

| 기록 | 인코딩 |
|---|---|
| (1층, 스테이지 3, 148.30초) | `1*10^11 + 3*10^8 + (10^8 - 14830)` = `100_299_985_170` |
| (2층, 스테이지 1, 300.00초) | `2*10^11 + 1*10^8 + (10^8 - 30000)` = `200_099_970_000` |

2층 기록이 1층 기록보다 큰 값 → 랭킹에서 상위 ✅

**한계:**
- 시간 상한 = 10^8 센티초 = 약 11.5일 (충분한 마진)
- 층 상한 이론상 무제한이지만 정수 정밀도 상 `9,999,999층`까지 안전
- MSW의 `integer` 타입 범위 확인 필요 (int64 이면 문제없음)

### 6.4 저장 & 조회 타이밍

- **로컬 저장 & 리더보드 등록**: 런 종료 시점 (사망 or 클리어) 서버에서 판정 후 순차 실행
  1. 서버에서 신기록 판정 (`bestScore` 갱신 여부)
  2. 갱신 시 → `_DataStorageService` 저장 → `RankingDataStorageLogic:SetScoreAndWait` 호출
  3. 두 작업 완료 후 로비 UI 갱신 신호 전송
- **글로벌 순위 조회**: 로비 진입 시 `RankingDataCacheLogic:GetMyRankingDataAndWait` 호출, 결과가 오면 §5.1 순위 라인 갱신
- **UI 반영 타이밍**: **서버 저장 완료 후** 반영 (즉시 반영은 실패 시 UI/데이터 불일치 위험)

## 8. 리스크 & 미결 사항

### 8.1 기술 리스크

- **ESC 일시정지 감지**: MSW 자체 일시정지 이벤트를 스크립트에서 감지 가능한지 확인 필요. `StageManager.combatPaused` 를 재활용할 수 있는지 조사.
- **스테이지 진행도 정규화**: `NormalsClearedThisFloor` + `ShopDoneThisFloor` + 보스 클리어 여부의 조합을 단일 순번으로 매핑하는 규칙 명확화 필요. 예: `stageOrdinal = NormalsClearedThisFloor * 2 + (ShopDoneThisFloor ? 1 : 0) + (bossCleared ? 100 : 0)` 같은 안이 필요.
- **랭킹 패키지 UUID 충돌**: `ranking-basic-package` 통합 시 기본 트리거 키(F2/F3/F4)가 기존 게임 조작과 충돌할 수 있음. UI 자동 등록 여부 확인 후 필요 시 비활성화하고 커스텀 트리거로 대체.
- **`SortableDataStorage` / `WorldConfig` 요구사항**: 랭킹 패키지가 요구하는 `PlayerEntityAuthorityCheck` 설정이 기존 게임 로직과 충돌하지 않는지 확인.
- **점수 정밀도**: mlua `integer` 가 int64인지 확인. §6.3 인코딩 최대값이 int32 범위(~2×10^9) 초과 가능성.

### 8.2 기획 미결 사항

- **계정 데이터 리셋 기능**을 유저에게 제공할지? (스피드런 니즈)
  -> 미제공
- **글로벌 리더보드 UI 스펙**: 초기 버전은 "본인 순위 숫자만" 표시 vs "상위 10명 리스트"까지 표시할지
  -> 상위 10명 리스트까지 표시, 맨 아래에는 자기 순위 숫자 표기
- **닉네임 정책**: 랭킹 패키지 기본은 MSW 계정 닉네임 사용. 별칭/커스텀 닉네임 지원 여부
  -> MSW 계정 닉네임 사용

### 8.3 밸런스 리스크

- 시간 지표 노출로 유저가 상점 이용·탐색을 회피할 수 있음. 스피드 로그라이트 정체성상 의도된 부작용이나, 상점/메타 업그레이드 사용 빈도를 모니터링.
- 타이머가 상점 중 정지되므로 상점 이용에 페널티 없음 → 유저가 "탐색은 자유, 전투만 빠르게" 를 선택할 수 있게 됨.

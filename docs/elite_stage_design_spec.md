# MapleRush 엘리트 스테이지 기능명세서

> 문서 상태: 구현 설계 기준
>
> 관련 문서: `stage_design_doc_ver3.md`, `event_stage_design_spec.md`(이벤트 명세 작성 시 본 문서의 용어·보정 규칙을 따른다)
>
> 범위: 기존 일반 전투 스테이지의 고위험·고보상 변형인 **엘리트 스테이지**. 이벤트의 상황문·선택 결과·불이익 관리는 이벤트 스테이지 명세에서 정의한다.

---

## 1. 목적과 역할

엘리트 스테이지는 현재 층의 일반 스테이지 후보를 그대로 사용하되, 그 안에 스폰되는 모든 일반 적을 강화하고 일반 보상에 엘리트 전용 보상을 추가하는 전투 노드다.

이번 구현은 **임시로 기존 일반 스테이지를 재사용**한다. 엘리트 전용 맵, 별도 적 편성, 별도 스폰·클리어 루프는 만들지 않는다. 선택된 일반 스테이지의 맵·스폰 지점·적 편성·재시작·클리어 흐름을 그대로 사용하고, 그 위에 엘리트 전투 문맥과 적·보상 보정만 적용한다. 향후 엘리트 전용 스테이지가 제작되면 이 재사용 규칙을 전용 맵·편성 규칙으로 교체한다.

| 구분 | 일반 스테이지 | 엘리트 스테이지 |
|---|---|---|
| 맵·테마·기본 적 편성 | 현재 로직 사용 | 선택된 일반 스테이지와 동일한 맵·스폰 지점·적 편성 재사용(임시) |
| 적 보정 | 층 체력 보정만 적용 | 층 보정 후 체력 ×2.0, 이동속도 ×1.3 |
| 보상 | 일반 보상 추첨 | 일반 보상 추첨 + 전용 보상 1개 이상 |
| 보스 대체 | 해당 없음 | 하지 않음 |
| 진행 슬롯 | 선택한 노드에서 1회 소비 | 선택한 노드에서 1회 소비 |

엘리트는 `노드 유형`이면서 `전투 유형`이다. 반면 이벤트는 노드 유형이지만 전투 유형이 아닐 수 있다. 구현에서는 두 개념을 한 문자열에 섞지 않는다.

```text
NodeKind: normal | elite | event
CombatStageType: normal | elite | boss | shop
```

## 2. 노드 생성 및 선택

보스 이전의 각 노드 선택 라운드마다 세 장의 카드를 독립 추첨한다.

| 카드 종류 | 가중치 | 확률 |
|---|---:|---:|
| 일반 | 5 | 50% |
| 엘리트 | 3 | 30% |
| 이벤트 | 2 | 20% |

- 같은 종류의 카드가 2개 또는 3개 나와도 허용한다.
- 일반 카드의 최소 보장과 종류 중복 방지는 적용하지 않는다.
- 일반·엘리트 카드는 현재 테마의 스테이지 덱에서 후보 스테이지를 배정받는다.
- 선택한 카드는 서버가 확정하고, 사망 후 재시작 때 카드·스테이지 유형·보정은 다시 추첨하지 않는다.

## 3. 전투 규칙

### 3.1 적 보정

엘리트 전투에 스폰되는 모든 일반 적에 아래 보정을 적용한다.

| 항목 | 값 | 적용 순서 |
|---|---:|---|
| 최대 체력 | ×2.0 | 모델 기본값 → 층 체력 보정 → 다음 전투 보정과 합연산 → 엘리트 보정 |
| 현재 체력 | 최대 체력과 동일 | 최종 최대 체력 계산 직후 설정 |
| 이동속도 | ×1.3 | 적 원본 이동속도에 곱연산 |
| 보스 | 적용하지 않음 | 엘리트는 보스 노드를 대체하지 않음 |

이벤트의 `다음 전투 적 체력 증가`(×1.5)와 엘리트 체력 보정(×2.0)이 겹치면, 두 보정의 **추가 체력 비율을 합연산**한다.

```text
최종 체력 = 기본 체력 × 층 체력 보정 × (1 + (엘리트 배율 - 1) + (이벤트 배율 - 1))

엘리트만: 기본 체력 × 층 체력 보정 × 2.0
이벤트만: 기본 체력 × 층 체력 보정 × 1.5
둘 다 적용: 기본 체력 × 층 체력 보정 × 2.5
```

이 규칙에서 체력 보정은 서로 곱하지 않는다. 이동속도 ×1.3에는 이벤트의 적 체력 보정이 영향을 주지 않는다.

### 3.2 시각적 식별

엘리트 전투에 스폰되는 모든 일반 적은 아래 시각 보정을 함께 적용한다. 보스와 투사체에는 적용하지 않는다.

| 항목 | 규칙 |
|---|---|
| 보라색 외곽선 | `SpriteRendererComponent.MaterialID`에 `EliteEnemyOutline` 머티리얼을 적용한다. 이 머티리얼은 MSW 기본 `Outline` 셰이더를 사용하고, 진하고 밝은 보라색 외곽선으로 설정한다. |
| 스프라이트 크기 | 적이 스폰될 때 저장한 원본 `TransformComponent.Scale`의 X·Y에 각각 `×1.25`를 적용한다. 좌우 반전의 부호와 Z 값은 보존한다. |
| 애니메이션 | 머티리얼과 변환 배율은 렌더러·엔티티 단위로 적용되므로 대기·이동·공격·피격·사망 등 모든 기존 애니메이션 프레임에도 동일한 외곽선과 1.25배 크기를 유지한다. 별도 애니메이션 클립을 만들지 않는다. |
| 전투 판정 | 크기 보정은 시각 연출 전용이다. 피격 범위, 적 공격 범위, 이동 충돌 범위는 일반 적과 동일하게 유지한다. 현재 전투 판정이 `TransformComponent.Scale`을 반영하므로, 엘리트 적용 시 `HitComponent` 크기·오프셋 등 관련 판정값을 역보정하여 최종 판정 크기가 원본과 같게 한다. |
| 기준점·재시작 | 발밑 기준점이 일반 적과 같게 유지되도록 스프라이트 피벗 또는 세로 오프셋을 보정한다. 재시작마다 새로 스폰된 적에 원본값 기준으로 한 번만 적용하며, 배율·외곽선이 누적되지 않게 한다. |

`EliteEnemyOutline`은 모든 엘리트 적이 공유하는 단일 머티리얼 에셋으로, MSW Maker에서 `Outline` 셰이더와 보라색·외곽선 두께를 설정해 준비한다. 적마다 런타임에 머티리얼 색을 변경하지 않는다. 서버가 스폰 문맥에 따라 `MaterialID`와 변환 배율을 적용하고, 동기화된 결과를 클라이언트는 렌더링만 한다.

`EliteEnemyOutline` 머티리얼이 없거나 적용에 실패하면 개발 로그에 오류를 남기고 QA 실패로 처리한다. 외곽선은 엘리트 식별의 필수 요건이며, 일반 적·보스·투사체에 남아 있으면 안 된다.

### 3.3 재시작 및 클리어

- 플레이어 사망 시 현재 엘리트 스테이지를 같은 적 편성·동일 보정으로 재시작한다.
- 재시작은 진행 슬롯 증가, 스테이지 덱 소모, 보상 추첨을 발생시키지 않는다.
- 모든 적 처치 후 일반 보상과 엘리트 전용 보상을 처리한다. 엘리트 전투 클리어 수는 별도 집계하며, 이미 선택 시 소비한 진행 슬롯을 다시 소비·증가시키지 않는다.
- 엘리트 클리어도 일반 스테이지와 동일하게 선택한 스테이지 카드를 덱에서 제거하고 직전 스테이지 기록을 갱신한다.

## 4. 보상

### 4.1 지급 순서

엘리트 클리어 시 서버는 다음 순서로 처리한다.

1. 현재 일반 스테이지의 메소 지급과 보상 추첨을 그대로 실행한다.
2. 엘리트 전용 보상 개수를 판정한다. 기본은 1개이며, **10% 확률로 2개**다.
3. 엘리트 전용 보상 풀에서 판정된 개수만큼 가중치 추첨해 적용한다.
4. 모든 보상 UI가 확정된 후 다음 노드 선택으로 넘어간다.

일반 보상 추첨은 기존과 조금 더 높게 능력치 70%, 아이템 90%, 능력 40%의 판정을 사용한다.

- 엘리트 전투의 일반 보상은 `elite` 전용 일반 보상표를 새로 만들지 않고, 기존 `normal` 보상 경로를 그대로 사용한다. 그 뒤에만 엘리트 전용 보상 추첨을 추가한다.

### 4.2 엘리트 전용 보상 풀

| ID | 보상 | 효과 | 가중치 |
|---|---|---|---:|
| `max_life_up` | 최대 목숨 증가 | 최대 목숨 +1, 현재 목숨 +1 | 0.5 |
| `move_speed_up` | 이동속도 증가 | 이번 런 동안 ×1.05 | 1 |
| `dash_charge_up` | 대시 충전 가속 | 이번 런 동안 ×1.05 | 1 |
| `attack_up` | 공격력 증가 | 이번 런 동안 ×1.05 | 1 |
| `attack_speed_up` | 공격속도 증가 | 이번 런 동안 ×1.05 | 1 |
| `dash_max_up` | 대시 최대 개수 증가 | 이번 런 동안 +1, 즉시 1회 충전 | 0.5 |
| `dash_invuln_up` | 대시 무적 시간 증가 | 이번 런 동안 ×1.20 | 0.5 |
| `meso_double` | 보유 메소 증가 | 현재 메소 ×2, 메소 상한으로 클램프 | 0.5 |
| `next_shop_free` | 다음 상점 무료화 | 다음 상점의 무작위 판매 품목 1개 가격을 0으로 예약 | 1 |

총 가중치는 7이며, 가중치 1 보상은 각각 14.29%, 가중치 0.5 보상은 각각 7.14%다.

- 엘리트 전용 보상은 최소 1개를 확정 지급한다.
- 전용 보상 2개 판정은 10% 확률이며, 같은 클리어에서 두 보상은 **중복 없이** 추첨한다.
- 같은 런에서 다른 엘리트 스테이지를 통해 동일 보상을 다시 얻는 것은 허용하며, 런 지속 능력치 증감은 곱연산으로 누적한다.

## 5. 상태 및 적용 안전 규칙

- 최대 목숨과 최대 대시 개수는 항상 1 이상이다.
- 현재 목숨은 언제나 최대 목숨 이하로 클램프한다.
- 메소 ×2는 프로젝트 메소 상한을 넘지 않는다.
- 런 지속 보상은 다음 층에도 유지하며 런 시작·게임 오버·전 층 클리어·런 포기 시 초기화한다.
- 보상 추첨, 스탯 변경, 상점 예약, 적 보정은 모두 서버가 판정한다. 클라이언트 UI는 결과를 표시하고 선택 요청만 보낸다.

## 6. UI 요구사항

### 6.1 노드 카드

엘리트 카드에는 `엘리트 전투` 유형을 고정 표기한다. 카드 테두리는 일반 카드와 분명히 구분되는 **진하고 밝은 보라색**으로 표시한다.

위험과 보상 상세 정보는 카드 위에 마우스를 올렸을 때 커서에 붙어 표시되는 **호버 툴팁**으로 제공한다.

- 툴팁은 커서를 따라가되, 카드 밖으로 커서가 벗어나면 즉시 숨긴다.
- 툴팁 내용은 두 줄로 표시한다: `적 강화 수치: 체력 ×2.0, 이동속도 ×1.3`, `보상: 일반 보상 + 엘리트 보상 (낮은 확률로 엘리트 보상 추가 획득)`.
- 툴팁은 카드 선택을 가리거나 클릭을 가로채지 않는다.
- 일반·이벤트 카드도 같은 호버 툴팁 방식으로 위험·보상 정보를 제공해 카드 UI의 상호작용 규칙을 통일한다.
- 모바일·터치 환경에서는 호버가 없으므로, 카드 탭 시 같은 안내를 먼저 표시하고 확인 후 선택하도록 제공한다.

현재 `HoverMaterial` 설계는 카드의 호버 시각 효과만 담당한다. 커서 추적형 호버 툴팁은 별도 클라이언트 전용 UI 책임으로 구현하며, 기존 호버 머티리얼 효과와 병행할 수 있다.

세 카드 모두 독립적으로 선택할 수 있어야 하며, 카드별 버튼 이벤트는 각각 `RequestSelectNode(1..3)`으로 서버에 전달한다.

### 6.2 보상 결과

엘리트 전용 보상은 1개를 확정 지급하며, 10% 확률로 중복 없는 전용 보상 2개를 지급한다.

- 보상 결과 화면에는 전용 보상 수를 명확히 표기한다. 예: `엘리트 보상 1개`, `엘리트 보너스! 전용 보상 2개`.
- 전용 보상 각각은 별도 행 또는 별도 카드로 표시하고, 효과·기간(이번 런/다음 상점)을 함께 표시한다.
- 적용값과 2개 보상 판정은 서버가 확정하며, 클라이언트는 이를 계산하거나 변경하지 않는다.

## 7. 현재 프로젝트 구조와의 구현 경계

| 대상 | 현재 상태 | 엘리트 구현 시 변경 책임 |
|---|---|---|
| `FloorManager` | 세 스테이지 후보만 만들고 일반으로 시작 | 카드별 `NodeKind`·선택된 전투 유형을 보존하고, 선택된 노드에서 진행 슬롯을 정확히 1회 소비하며 전투 클리어 수는 별도 처리 |
| `StageManager` | `StageType`은 normal/shop/boss, 일반 적을 스폰 | `elite` 전투 유형과 재시작에도 유지되는 스폰 컨텍스트를 추가. `StartStageAt`은 선택된 일반 스테이지의 편성·스폰 지점을 그대로 사용한 채 전투 유형만 `elite`로 시작해야 하며, 별도 `StartStage("elite")`로 임의 편성을 다시 추첨하면 안 됨 |
| `EnemyHealth` | 층 체력 보정 후 HP 초기화 | 층 보정 뒤 이벤트·엘리트 체력 보정을 합연산할 기준값·플래그 제공 |
| `EnemyMelee`·`EnemyRanged`·`EnemyChaser` | 각자 원본 이동속도로 이동 | 원본 속도를 변경하지 않고 엘리트 속도 배율을 이동 계산에 적용 |
| `EliteModifier`(신규 공통 보정) | 없음 | 스폰 시 엘리트 적의 원본 변환·판정값을 저장하고, 보라색 외곽선·1.25배 시각 크기·판정 역보정을 한 번만 적용. 모든 애니메이션 상태와 재시작에서도 같은 결과 보장 |
| `RewardManager` | 일반/보스 보상만 추첨 | 전용 보상 개수 1/2 판정, 가중치 추첨, 적용, 로그 추가 |
| `GameStateManager` | 메소·목숨·공격력만 런 상태로 관리 | 이동·공격속도·대시 관련 런 보정과 다음 상점 예약의 단일 서버 상태 추가. 일반 클리어 수와 별도로 `EliteClears`를 집계 |
| `ShopManager` | 4개 고정 가격만 관리 | 가격 생성 전에 무료 품목 예약을 반영하고 상점 종료 시 예약 해제 |
| `NodeSelectController` | 현재 1번 카드 버튼만 연결 | 3개 카드의 유형·호버 툴팁·클릭을 모두 연결 |

### 구현 주의점

`StageManager.ResetStage()`가 적을 스폰하는 구조이므로, 스폰 뒤에 체력·속도를 덮어쓰는 방식은 적 `OnBeginPlay()`의 층 보정과 순서 경쟁을 만들 수 있다. 선택된 전투 유형과 다음 전투 체력 보정을 **스폰 전에** 서버 상태로 확정하고, 적 초기화 시점에 `층 체력 보정 → 이벤트·엘리트 체력 보정 합연산 → 엘리트 시각·판정 보정` 순서로 계산한다.

현재 `StageClear()`는 보스가 아닌 전투를 일반 클리어로 처리하므로, 엘리트 클리어에서는 일반 보상 경로를 유지하되 `NormalClears`와 `EliteClears`의 집계 기준을 분리해야 한다. `RewardManager:RollRewards("elite")`가 일반 보상 경로를 잃거나 보상 추첨이 중복되지 않도록 서버 흐름을 명확히 분기한다.

## 8. 용어 및 연계 문서 일관성

| 용어 | 본 문서의 의미 | 연계 기준 |
|---|---|---|
| 노드 유형 | 선택 카드의 종류(`normal`/`elite`/`event`) | 스테이지 기획서의 3분기 노드 구조를 확장 |
| 전투 유형 | 실제 전투 처리 종류(`normal`/`elite`/`boss`/`shop`) | `StageManager.StageType` 확장 기준 |
| 진행 슬롯 | 보스 이전 노드 선택에서 소비하는 1회 진행 단위 | 전투 클리어 수와 별도로 관리하며 이벤트 선택도 1회 소비 |
| 다음 전투 1회 | 다음 일반 또는 엘리트 전투 한 번에만 유효한 예약 효과 | 이벤트 명세의 기간 용어와 통일 |
| 이번 런 동안 | 런 종료 전까지 다음 층을 넘어 유지되는 효과 | 기존 런 상태와 동일한 생명주기 |
| 호버 툴팁 | 마우스 호버 시 커서를 따라 표시되는 안내 UI | 기존 `HoverMaterial`의 시각 효과와 구분 |

## 9. 수용 기준

- 카드 3장이 각각 독립 가중치 5:3:2로 추첨되고, 엘리트 카드가 0~3장 나올 수 있다.
- 엘리트 선택 시 현재 테마의 일반 스테이지 적 편성으로 전투가 시작된다.
- 이번 구현에서는 선택된 일반 스테이지의 맵·스폰 지점·적 편성·재시작·클리어 흐름을 재사용하며, 엘리트 전용 맵·편성은 만들지 않는다.
- 모든 일반 적의 체력은 층 보정 후 ×2.0, 이동속도는 ×1.3이며 시각적으로 식별된다.
- 모든 엘리트 일반 적은 보라색 외곽선과 원본 대비 1.25배 스프라이트 크기를 유지한다. 모든 애니메이션 상태에서도 동일하며, 보스·투사체·일반 적에는 적용되지 않는다.
- 1.25배 시각 보정으로 적의 피격 범위·공격 범위·이동 충돌 범위가 커지지 않고, 재시작 때 배율이나 외곽선이 누적되지 않는다.
- 이벤트 체력 ×1.5와 엘리트 체력 ×2.0이 겹치면 최종 체력 보정은 ×2.5다.
- 사망 후 재시작에도 선택 스테이지와 엘리트 보정이 유지되고 카드가 재추첨되지 않는다.
- 클리어 시 일반 보상과 엘리트 전용 보상 1개 이상이 적용되고, 10% 확률로 중복 없는 전용 보상 2개가 적용된다.
- 엘리트 카드에는 진하고 밝은 보라색 테두리가 표시되고, 호버 툴팁으로 위험·보상 정보를 안내한다.
- 런 종료 시 모든 엘리트 런 지속 보상과 다음 상점 무료 예약이 초기화된다.
